Direct Rename (Zero SSD Writes) vs. In-Container Metadata Tagging

Choose how CineTag manages and organizes your processed video files:

🚀 Direct Rename Only (Zero Extra SSD Writes & 0% Corruption Risk — Default / Recommended):

Renames the video file on disk and updates accompanying sidecars (.txt, .json, .srt, .nfo). Disclaimer: Filesystem renaming updates only the directory table entry / inode pointer without rewriting any video payload bytes. This creates 0 extra writes on your SSD and has 0% risk of stream corruption.

🏷️ In-File Container Tagging (Optional):

Re-muxes the video container via FFmpeg (-c copy) to embed Title, Description, and Keywords directly inside MP4/MOV container atoms and Windows Explorer Xtra tags. Because stream copying writes duplicate stream data to disk, it creates extra writes on your drive and creates a temporary .bak safety backup until stream duration and integrity are verified.

ℹ️ What this controls: Minimum neural probability required to recognize a shape as an actual human face (rejecting non-face artifacts).

  • Higher values (0.75 - 0.90): Recommended to eliminate false positives. Enforces strict verification of eyes, nose, and mouth. Rejects hands, elbows, knees, cloth folds, and textured background patterns.
  • Lower values (0.30 - 0.60): Increases sensitivity for distant, blurred, or partially shadowed faces, but may capture false positives.

  • Higher Distance (0.50 - 0.95): Recommended if the same person is split into multiple entries. Clusters varied camera angles, head turns, expressions, smiles, profile views, and lighting changes into a single individual.
  • Lower Distance (0.20 - 0.40): Stricter identity separation. Distinguishes very similar-looking siblings or relatives, but may create multiple profiles for the same person if lighting or hairstyle changes.

🛡️ SSD Safety & Direct Renaming Disclaimer:

Direct renaming (auto_rename) operates instantly at the filesystem directory index level. It does not copy, re-encode, or rewrite any video data, so it creates 0 extra writes on your SSD and has 0% risk of stream corruption. In-file container tagging re-muxes the container with FFmpeg to embed tags, which writes duplicate stream data to disk.
